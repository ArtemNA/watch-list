# Step 13 — Сторінка-превью фільму з пошуку (без додавання)

**Передумови:** Steps 01–10 (пошук, збагачення, i18n uk/en/ru). НЕ залежить від
Steps 11–12 — можна виконувати до них. Прочитай ARCHITECTURE §4 (стратегія API).

## Мета

З результатів пошуку можна відкрити повноцінну сторінку фільму/серіалу БЕЗ
додавання в бібліотеку: тільки інформація з API (постер, опис, жанри, рейтинги,
«де подивитись») + кнопки додавання. Без жодних юзерських блоків (нотатки,
посилання, статус, оцінка).

## Ключові рішення (зафіксовані)

- Роут: **`/preview/:kind/:tmdbId`** (напр. `/preview/movie/438631`). Deep-link
  працює: сторінка сама тягне дані по параметрах, нею можна поділитись.
- **НІЧОГО не пишеться в IndexedDB** — дані живуть тільки в пам'яті сторінки.
  Це принципова різниця від item-page: превью не «айтем», а вітрина API.
- Якщо фільм ВЖЕ в бібліотеці (збіг по tmdbId) — превью не показується:
  редірект на справжню `/item/:id` (і навпаки, клік по картці «У бібліотеці»
  в пошуку веде одразу на item-page, як зараз).

## Завдання

1. **Спільні презентаційні компоненти** (щоб не дублювати item-page):
   винести з `item-page` у `features/item/` (або `shared/`) чисті
   компоненти-блоки з `input()`-сигналами:
   - `media-header` (постер, назва+оригінальна, рік, тип, жанри, опис,
     лінки TMDB↗/IMDb↗),
   - `media-ratings` (TMDB/IMDb/RT/Metacritic),
   - `media-watch-providers` (Підписка/Оренда/Купівля + атрибуція JustWatch).
   item-page переходить на ці компоненти БЕЗ зміни вигляду (регресія —
   критерій приймання).
2. **Завантаження даних превью** (`features/preview/preview.service.ts` або
   розширення metadata-сервісу): TMDB details (`language` = мова UI,
   `append_to_response=external_ids,watch/providers,translations`) → якщо є
   imdbId → OMDb рейтинги. Перевикористати ІСНУЮЧІ мапери
   (`tmdb-mapping`/`metadata-mapping`/`omdb-api`) — нових маперів не писати.
   Кеш у пам'яті на сесію (Map по `kind:id:lang`), щоб «назад-вперед» з
   пошуку не бив у API повторно. OMDb-помилки тихі (як на item-page).
3. **`features/preview/preview-page`** (роут `/preview/:kind/:tmdbId`):
   - стани: спінер завантаження / помилка з «Повторити» / офлайн
     (app-empty-state, як у пошуку) / контент;
   - контент: `media-header` + `media-ratings` + `media-watch-providers`;
   - **блок додавання**: split-кнопка «Додати» (want) + «Додати як…»
     (watching/watched/dropped) — та сама `app-split-button` і той самий
     `SearchService.addToLibrary`-шлях (щоб мапінг деталей у MediaItem був
     один); після додавання — редірект на `/item/:id` зі снекбаром;
   - якщо на вході tmdbId вже в бібліотеці → миттєвий redirect на item-page
     (без блимання превью);
   - кнопка «Назад до пошуку» (location.back(), а не routerLink — щоб
     зберігся стан пошуку/скрол).
4. **Пошук**: постер і назва на картці результату стають клікабельними →
   `/preview/:kind/:tmdbId` (для «У бібліотеці» — на `/item/:id`, як і чіп).
   Split-кнопка «Додати» на картці ЛИШАЄТЬСЯ (швидкий шлях без переходу).
   У режимі linkItemId (зв'язування ручного айтема, Step 06) клік по картці
   НЕ веде на превью — там свій флоу «Обрати».
5. i18n: усі нові рядки в ТРЬОХ словниках (uk/en/ru). Мобільна верстка 360px.
   `/dev/ui` не чіпати (нові компоненти — сторінкові, не shared/ui).
6. Тести: сервіс превью (кеш по kind:id:lang, тихий фейл OMDb), redirect-логіка
   «вже в бібліотеці» (чиста функція/computed), регресія item-page
   (існуючі тести мають лишитись зеленими після винесення компонентів).

## Критерії приймання

- [x] З пошуку клік по постеру/назві відкриває превью з описом, рейтингами
      і «де подивитись» — фільм НЕ з'являється в бібліотеці і в IndexedDB.
- [x] «Додати як → Подивився» на превью → редірект на item-page, фільм у
      бібліотеці зі статусом watched.
- [x] Превью фільму, який уже в бібліотеці, редіректить на item-page.
- [x] Deep-link `/preview/movie/438631` працює з чистої вкладки; зміна мови UI
      на відкритому превью перезавантажує дані мовою UI.
- [x] «Назад» повертає до пошуку зі збереженим запитом.
- [x] item-page виглядає як раніше (компоненти винесено без візуальних змін).
- [x] build/lint/тести чисті; обидві теми; 360px; процеси зупинені.

## Заборонено

- Жодного запису превью-даних у IndexedDB/Dexie.
- Не дублювати мапери TMDB/OMDb і розмітку блоків — тільки перевикористання.

## Результат виконання

> **Ревью архітектора (2026-07-11): ПРИЙНЯТО.** Перевірено: build (789kB,
> у бюджеті)/lint + 115 web і 17 api тестів; живцем з реальними TMDB/OMDb:
> пошук «interstellar» → клік по постеру → превью з укр назвою/описом,
> 4 рейтингами і провайдерами, БЕЗ запису в IndexedDB (лічильник айтемів
> звірено до/після); «Додати як → Подивився» → редірект на item-page, у базі
> айтем зі status=watched і metadataLang=uk; повторний deep-link на доданий
> фільм → миттєвий редірект на item-page; «Назад до пошуку» зберіг запит.
> Код чистий: кеш промісів з видаленням при фейлі (retry реально повторює),
> `display: contents` для порожніх блоків — акуратне рішення. Зауважень немає.

**Спільні компоненти** (`web/src/app/features/item/`): `media-header` (постер,
назва+оригінальна, рік/тип, жанри, опис, TMDB↗/IMDb↗ — лінки обчислюються
всередині компонента з `kind`/`tmdbId`/`imdbId`, а не передаються ззовні),
`media-ratings` (TMDB/IMDb/RT/Metacritic, ховає себе, якщо рейтингів немає),
`media-watch-providers` (Підписка/Оренда/Купівля + атрибуція, ховає себе, якщо
даних немає). Усі три — `input()`-сигнали, обрано `features/item/` (не
`shared/`), бо це доменні медіа-блоки, а не елементи каталогу `/dev/ui`.
Кожен компонент має `:host { display: contents }` — інакше порожній рендер
(коли рейтингів чи провайдерів немає) лишав би в DOM порожній flex-item і
`item-page`/`preview-page` отримували б зайвий gap між сусідніми картками;
з `display: contents` порожній компонент повністю прозорий для layout'у
батька. `item-page` перейшов на ці компоненти без зміни розмітки/стилів
навколо них (`tmdbUrl`/`imdbUrl`/`ratingEntries` видалені з `ItemPage` —
логіка тепер у відповідних компонентах).

**`features/preview/preview.service.ts`** — TMDB details (`language` = мова
UI, ті самі `append_to_response`) → якщо є imdbId → OMDb (тиха помилка, як на
item-page). Перевикористано `mapCommonDetailsFields` і `extractWatchProviders`
з `tmdb-mapping`/`metadata-mapping` — нових мапінгів не написано. Кеш —
`Map<string, Promise<PreviewData>>` по ключу `kind:id:lang`; провальний запит
видаляється з кешу перед прокиданням помилки, щоб «Повторити» реально
повторював виклик, а не переграв ту саму відмову.

**`features/preview/preview-page`** на `/preview/:kind/:tmdbId`: порядок
станів — невалідні route-параметри (kind не 'movie'/'tv' або tmdbId не
позитивне ціле) → «посилання не працює»; вже в бібліотеці (чиста функція
`findExistingItemId(items, kind, tmdbId)` з `preview-redirect.ts`) → редірект
у КОНСТРУКТОРІ через `effect` (до першого рендеру контенту — без блимання
превью), причому ця перевірка йде ДО офлайн-перевірки, бо резолв по
IndexedDB не потребує мережі; далі офлайн-empty-state; далі спінер/помилка/
контент. Довантаження при зміні мови UI на відкритій сторінці — той самий
guard-по-ключу підхід, що на item-page (Step 06). «Назад до пошуку» —
`Location.back()` (Angular-обгортка над `history.back()`), не `routerLink`,
щоб зберегти стан/скрол пошуку. Блок додавання — split-кнопка, що збирає
синтетичний `SearchResult` з даних превью і викликає ІСНУЮЧИЙ
`SearchService.addToLibrary` (той самий шлях, що з картки пошуку) — свідомий
компроміс: TMDB details тягнеться вдруге (раз для показу превью, раз
усередині `addToLibrary`), але мапінг у `MediaItem` лишається в одному місці,
як і вимагала специфікація.

**Пошук**: постер і назва картки обгорнуті в `<a [routerLink]="previewLink(result)">`
(окремо постер, окремо назва — щоб зона кліку не зачіпала блок дій).
`previewLink()` повертає `null` у режимі `linkItemId` (лінкування ручного
айтема, Step 06 — там свій флоу «Обрати»), `/item/:id` для «У бібліотеці»
(як і чіп), інакше `/preview/:kind/:id`. Split-кнопка «Додати» на картці не
чіпалась.

**i18n**: додано лише реально нові рядки (`preview.back`, `preview.loading`,
`preview.error.title`, `preview.offline.title/description`,
`preview.notFound.title/description`, `preview.add.label`) у трьох
словниках. Решта («Додати», «Додати як…», «Повторити», снекбари додавання,
«Скасувати») перевикористані з існуючих ключів `search.*`/`common.*` — той
самий текст, дублювати сенсу не було.

**Тести**: `preview-redirect.spec.ts` (4 тести — збіг kind+tmdbId, відсутність
збігу, різний kind з тим самим tmdbId, айтем без tmdbId) і
`preview.service.spec.ts` (7 тестів — мердж OMDb по imdbId, відсутність
виклику OMDb без imdbId, тиха помилка OMDb, кеш по kind:id:lang, різна мова/
kind = різний кеш-ключ, провал НЕ кешується). Сторінкові компоненти
(`preview-page`, як і `item-page`/`search-page` раніше) без окремих
component-specs — за існуючою конвенцією проєкту; перевірено вручну.
Регресія item-page: власних тестів на item-page не було й раніше, перевірено
вручну (обидві теми, 360px, 1280px) — без відхилень.

**Ручна перевірка в браузері** (справжні TMDB/OMDb, `dev:api` + `ng serve`):
пошук «Dune» → клік по постеру/назві "Dune" (2021) → превью з описом,
рейтингами (TMDB 7.8, IMDb 8.0, RT 83%, MC 74) і «Де подивитись»; «Додати
як → Подивився» → редірект на item-page зі статусом Watched; бібліотека
після цього містить РІВНО 1 айтем (перегляд кількох інших превью — Dune:
Part Two, Dune 2020 без OMDb-рейтингів/провайдерів — нічого не додав у
IndexedDB); deep-link `/preview/movie/438631` в бібліотеці → миттєвий
редірект на item-page без блимання; deep-link на новий tmdbId з чистого
переходу → превью вантажиться; зміна мови на відкритому превью (en→uk)
перезавантажила заголовок/опис/усі підписи мовою UI; «Назад до пошуку»
коректно спрацював через `history.back()`; невалідний tmdbId (`/preview/movie/abc`)
→ «Це посилання не працює»; неіснуючий tmdbId (`999999999`) → «Не вдалося
завантажити дані» + «Повторити» (повторний клік коректно повторює запит,
без падіння в консоль); режим `?linkItemId=...` — картки пошуку БЕЗ
прев'ю-лінків (тільки «Обрати»/чіп «У бібліотеці»); 360px — превью і
item-page без розвалу (грід 2 колонки в пошуку, стек «Додати в бібліотеку»
+ split-кнопка); light+dark теми — без зайвих gap'ів між картками
(підтверджує коректність `display: contents`). Консоль без помилок на всіх
кроках.

**Перевірки якості**: `npm run build` (789.54kB initial, у межах бюджету
800kB, 0 warnings), `npm run lint`/`lint:api` чисті, `npm run typecheck:api`
чистий, `npm test` — 115/115 web (104 було + 11 нових), `npm run test:api` —
17/17. Dev-сервери (`ng serve` :4201, `dev:api` :3000) зупинені явно після
перевірки, порти звільнені.

**Відхилення від плану**: немає — усі задачі й заборони (нічого в IndexedDB,
без нових мапінгів) виконано так, як специфіковано.
