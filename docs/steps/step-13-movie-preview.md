# Step 13 — Сторінка-превью фільму з пошуку (без додавання)

**Передумови:** Steps 01–10 (пошук, збагачення, i18n uk/en/ru). НЕ залежить від
Steps 11–12 — можна виконувати до них. Прочитай ARCHITECTURE §4 (стратегія API).

## Мета

З результатів пошуку можна відкрити повноцінну сторінку фільму/серіалу БЕЗ
додавання в бібліотеку: тільки інформація з API (постер, опис, жанри, рейтинги,
«де подивитись») + кнопки додавання. Без жодних юзерських блоків (нотатки,
посилання, статус, оцінка).

## Ключові рішення (зафіксовані)

- Роут: **`/preview/:kind/:tmdbId`** (напр. `/preview/movie/438631`). Deep-link
  працює: сторінка сама тягне дані по параметрах, нею можна поділитись.
- **НІЧОГО не пишеться в IndexedDB** — дані живуть тільки в пам'яті сторінки.
  Це принципова різниця від item-page: превью не «айтем», а вітрина API.
- Якщо фільм ВЖЕ в бібліотеці (збіг по tmdbId) — превью не показується:
  редірект на справжню `/item/:id` (і навпаки, клік по картці «У бібліотеці»
  в пошуку веде одразу на item-page, як зараз).

## Завдання

1. **Спільні презентаційні компоненти** (щоб не дублювати item-page):
   винести з `item-page` у `features/item/` (або `shared/`) чисті
   компоненти-блоки з `input()`-сигналами:
   - `media-header` (постер, назва+оригінальна, рік, тип, жанри, опис,
     лінки TMDB↗/IMDb↗),
   - `media-ratings` (TMDB/IMDb/RT/Metacritic),
   - `media-watch-providers` (Підписка/Оренда/Купівля + атрибуція JustWatch).
   item-page переходить на ці компоненти БЕЗ зміни вигляду (регресія —
   критерій приймання).
2. **Завантаження даних превью** (`features/preview/preview.service.ts` або
   розширення metadata-сервісу): TMDB details (`language` = мова UI,
   `append_to_response=external_ids,watch/providers,translations`) → якщо є
   imdbId → OMDb рейтинги. Перевикористати ІСНУЮЧІ мапери
   (`tmdb-mapping`/`metadata-mapping`/`omdb-api`) — нових маперів не писати.
   Кеш у пам'яті на сесію (Map по `kind:id:lang`), щоб «назад-вперед» з
   пошуку не бив у API повторно. OMDb-помилки тихі (як на item-page).
3. **`features/preview/preview-page`** (роут `/preview/:kind/:tmdbId`):
   - стани: спінер завантаження / помилка з «Повторити» / офлайн
     (app-empty-state, як у пошуку) / контент;
   - контент: `media-header` + `media-ratings` + `media-watch-providers`;
   - **блок додавання**: split-кнопка «Додати» (want) + «Додати як…»
     (watching/watched/dropped) — та сама `app-split-button` і той самий
     `SearchService.addToLibrary`-шлях (щоб мапінг деталей у MediaItem був
     один); після додавання — редірект на `/item/:id` зі снекбаром;
   - якщо на вході tmdbId вже в бібліотеці → миттєвий redirect на item-page
     (без блимання превью);
   - кнопка «Назад до пошуку» (location.back(), а не routerLink — щоб
     зберігся стан пошуку/скрол).
4. **Пошук**: постер і назва на картці результату стають клікабельними →
   `/preview/:kind/:tmdbId` (для «У бібліотеці» — на `/item/:id`, як і чіп).
   Split-кнопка «Додати» на картці ЛИШАЄТЬСЯ (швидкий шлях без переходу).
   У режимі linkItemId (зв'язування ручного айтема, Step 06) клік по картці
   НЕ веде на превью — там свій флоу «Обрати».
5. i18n: усі нові рядки в ТРЬОХ словниках (uk/en/ru). Мобільна верстка 360px.
   `/dev/ui` не чіпати (нові компоненти — сторінкові, не shared/ui).
6. Тести: сервіс превью (кеш по kind:id:lang, тихий фейл OMDb), redirect-логіка
   «вже в бібліотеці» (чиста функція/computed), регресія item-page
   (існуючі тести мають лишитись зеленими після винесення компонентів).

## Критерії приймання

- [ ] З пошуку клік по постеру/назві відкриває превью з описом, рейтингами
      і «де подивитись» — фільм НЕ з'являється в бібліотеці і в IndexedDB.
- [ ] «Додати як → Подивився» на превью → редірект на item-page, фільм у
      бібліотеці зі статусом watched.
- [ ] Превью фільму, який уже в бібліотеці, редіректить на item-page.
- [ ] Deep-link `/preview/movie/438631` працює з чистої вкладки; зміна мови UI
      на відкритому превью перезавантажує дані мовою UI.
- [ ] «Назад» повертає до пошуку зі збереженим запитом.
- [ ] item-page виглядає як раніше (компоненти винесено без візуальних змін).
- [ ] build/lint/тести чисті; обидві теми; 360px; процеси зупинені.

## Заборонено

- Жодного запису превью-даних у IndexedDB/Dexie.
- Не дублювати мапери TMDB/OMDb і розмітку блоків — тільки перевикористання.
