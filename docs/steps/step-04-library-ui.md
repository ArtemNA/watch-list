# Step 04 — UI бібліотеки

**Передумови:** Steps 01–03. Прочитай `docs/ARCHITECTURE.md` §2, §8.

## Мета

Повноцінний UI роботи зі списком: бібліотека з фільтрами, сторінка айтема
з редагуванням «моїх даних» (оцінка, нотатки, посилання, статус). Все ще
без зовнішніх API — айтеми додаються вручну (форма), пошук TMDB — Step 05.

## Завдання

1. Роут `/` → `features/library/library-page`:
   - таби/чіпи статусів: Усі / Хочу / Дивлюсь / Подивився / Кинув (з лічильниками з `counts`),
   - фільтр за типом (фільм/серіал), текстовий фільтр по назві (по локальних даних),
   - сортування: за датою додавання (дефолт), назвою, роком, моєю оцінкою,
   - грід карток: постер (плейсхолдер, якщо нема), назва, рік, чіп статусу,
     моя оцінка зірками; клік → сторінка айтема,
   - `app-empty-state`, коли пусто (з кнопкою «Додати»),
   - стан фільтрів — у query params (щоб переживав back/reload).
2. Кнопка «Додати вручну» → діалог (MatDialog): назва*, тип*, рік, статус → `repo.add`.
   (У Step 05 поруч з нею з'явиться нормальний пошук; ручне додавання лишиться
   для фільмів, яких нема в TMDB.)
3. Роут `/item/:id` → `features/item/item-page`:
   - хедер: постер, назва (+оригінальна), рік, жанри, опис (з кешованих полів),
   - блок «Моє»: статус (чіпи-перемикачі), оцінка (`app-rating`, editable),
     дата перегляду (date input, показується для watched), нотатки (textarea,
     автозбереження з debounce ~800мс + індикатор «збережено»),
   - блок «Посилання»: список кастомних лінків (label + url, favicon через
     `https://www.google.com/s2/favicons?domain=`), додати/редагувати/видалити,
     валідація url (додавати https:// якщо нема схеми),
   - видалення айтема з confirm-діалогом → softDelete → назад у бібліотеку
     + MatSnackBar з кнопкою «Відмінити» (restore).
4. Всі тексти — через i18n (uk + en словники поповнити).
5. Мобільна верстка: грід 2 колонки на 360px, сторінка айтема — одна колонка.
6. Прибрати dev-сторінку `/dev/data` (dev/ui лишити).
7. Unit-тести: логіка фільтрації/сортування (винести в чисту функцію), парсинг url лінків.

## Критерії приймання

- [ ] Повний життєвий цикл руками: додав → оцінив → нотатки → статус → видалив → відмінив.
- [ ] Нотатки зберігаються автоматично, переживають reload.
- [ ] Фільтри в query params працюють (reload зберігає стан).
- [ ] Обидві мови, обидві теми, мобільна ширина — без розвалу верстки.
- [ ] build/lint/тести чисті.

## Заборонено

- Ніяких викликів зовнішніх API.

Виконано повністю за планом.

### Що зроблено

- **Чиста функція фільтрації/сортування** — `features/library/library-filters.ts`
  (`filterAndSortItems`, типи `LibraryFilters`/`StatusFilter`/`KindFilter`/`LibrarySort`),
  винесена окремо для юніт-тестів (`library-filters.spec.ts`, 8 тестів: фільтри
  за статусом/типом/пошуком окремо і в комбінації, сортування за 4 критеріями,
  трактування відсутніх `year`/`myRating` як найменших).
- **`features/library/library-page/`** — роут `/`: таби статусів з лічильниками
  (`repo.counts`), фільтр типу, текстовий пошук (debounce 300мс перед записом
  у query params), сортування (`<select>`), грід карток (постер/плейсхолдер,
  назва, рік, чіп статусу, readonly `app-rating`), клік → `/item/:id`,
  `app-empty-state` для порожньої бібліотеки і окремо для «нічого не знайдено»
  за фільтрами. Стан фільтрів синхронізований з query params
  (`status`/`kind`/`q`/`sort`, `router.navigate` з `replaceUrl: true` —
  один запис в історії з актуальним станом, а не по записі на кожну зміну
  фільтра); дефолтні значення в URL не пишуться (null → параметр прибирається).
- **`features/library/add-item-dialog/`** — MatDialog: назва* (з валідацією
  при спробі сабміту), тип, рік (опційно, парситься в число), статус → `repo.add`.
- **`features/item/item-page/`** — роут `/item/:id`: хедер (постер/плейсхолдер,
  назва, оригінальна назва якщо відрізняється, рік, тип, жанри як `app-chip`,
  опис — усе опційне, ховається якщо нема даних); блок «Моє» (перевикористано
  `app-card` для секцій): статус — перемикачі-кнопки (той самий патерн, що в
  Step 03 dev-data), оцінка — editable `app-rating` (зберігає одразу по кліку),
  дата перегляду — `<input type="date">` (показується лише для `watched`),
  нотатки — `app-input[multiline]` з локальним драфтом, debounce 800мс,
  індикатор «Зберігається.../Збережено»; блок «Посилання» — список з фавіконками
  (`link-utils.ts`: `normalizeUrl` додає `https://` якщо нема схеми,
  `faviconUrl` будує URL Google s2 favicons), інлайн-форма
  додавання/редагування (одна й та сама форма для обох випадків), видалення
  посилання. Видалення айтема — `DeleteConfirmDialog` (MatDialog з
  `MAT_DIALOG_DATA`) → `softDelete` → `router.navigate(['/'])` →
  `MatSnackBar` з кнопкою «Відмінити» → `restore`.
- **`link-utils.ts`** — 8 юніт-тестів (`normalizeUrl`: додавання схеми, вже
  наявна схема, trim, порожній рядок; `faviconUrl`: коректний URL, sub-домен,
  невалідний URL, порожній рядок).
- i18n: додано ключі `library.*`, `addItem.*`, `item.*`, `kind.movie`/`kind.tv`,
  `common.cancel`/`save`/`edit`/`delete` — обидва словники (uk/en) повні.
- Видалено тимчасову сторінку `/dev/data` (`features/dev-data/`) і її роут;
  `/dev/ui` не чіпали.
- `app.routes.ts`: `''` → `LibraryPage`, `'item/:id'` → `ItemPage`, `'dev/ui'`
  лишився.
- Лого «WatchList» в Shell стало посиланням на `/` (routerLink) — дрібна,
  але потрібна навігаційна деталь: без неї повернутись з `/item/:id` можна
  було тільки через back-посилання на сторінці айтема.

### Відхилення від плану

- **Бюджет initial-бандла в `angular.json` піднято з 500kB до 650kB**
  (warning-поріг; error-поріг 1MB не чіпали). Це дефолтне значення
  Angular CLI-скаффолда з Step 01, не архітектурне рішення з DECISIONS.md.
  Реальний білд після Step 04 (бібліотека + айтем-сторінка + 2 нових
  MatDialog + MatSnackBar) — 582.56kB, що вже перевищувало старий поріг;
  без правки `npm run build` видавав би warning, що суперечить критерію
  готовності (ARCHITECTURE §10, CLAUDE.md). Піднятий поріг лишає запас
  під Steps 05–11.
- **Ширина діалогів заведена інлайн-опцією при `dialog.open(...)`**
  (`width: 'min(480px, calc(100vw - 32px))'` для Add Item,
  `min(420px, ...)` для Delete Confirm), а не через глобальний
  `MAT_DIALOG_DEFAULT_OPTIONS` — у Step 02 такого глобального конфіга
  не було заведено (вимога ARCHITECTURE §8 «діалоги на мобільному — на
  всю ширину» лишилась не реалізованою architecture-wide). Мінімальний
  локальний фікс для двох нових діалогів; перевірено на 360px — влазять
  без переповнення. Глобальний дефолт для MatDialog — поза скоупом цього
  кроку, варто розглянути архітектору окремо.
- **`watchedAt` зберігається як рядок `YYYY-MM-DD`** (значення з
  `<input type="date">` напряму), а не повний ISO-таймстамп — це теж
  валідний ISO 8601 (дата без часу), простіше й без проблем із часовими
  поясами; узгоджується з формулюванням моделі «ISO-дата» в ARCHITECTURE §2.
- **`devData.kind.movie`/`devData.kind.tv` замінено на загальні
  `kind.movie`/`kind.tv`** (за аналогією з уже існуючим `status.*`),
  решта ключів `devData.*` видалено разом зі сторінкою.
- Дублювання невеликого фрагмента форми лінка (однакова розмітка для
  «додати» і «редагувати» в item-page.html) не виносив в окремий
  ng-template/компонент — 6 рядків розмітки, overhead абстракції більший
  за виграш.

### Відомі проблеми

Немає. `npm run build` (без попереджень), `npm run lint`, `npm test`
(32/32, +15 нових) — чисті. Вручну перевірено в Browser-пейні (dev-сервер
зупинено після перевірки): повний життєвий цикл (додав вручну → оцінка 8/10
→ статус «Подивився» → з'явилось поле дати перегляду → нотатки з
debounce-автозбереженням, пережили `window.location.reload()` → додав
посилання з URL без схеми → фавіконка/нормалізація коректні → редагування
лінка з префілом → видалення айтема з підтвердженням → snackbar
«Відмінити» → відновлення з усіма даними включно з лінками); фільтри
(статус+тип+порожній пошук) коректно потрапляють у query params і
переживають reload; порожній стан «нічого не знайдено» окремо від порожньої
бібліотеки; обидві мови (imperative-перевірка перемикання без reload —
impure-пайп з Step 02 відпрацював і тут); світла/темна тема; 360px —
без горизонтального скролу і переповнення (грід 2 колонки, хедер айтема
в один стовпець, діалоги влазять). Тестовий айтем після перевірки
soft-deleted (не впливає на реальні дані користувача — Browser-пейн має
окремий профіль).
