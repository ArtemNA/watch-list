# WatchList — головний план проекту

> **Статус-файл.** Це головний документ проекту. Кожен агент (архітектор чи виконавець)
> ПІСЛЯ завершення роботи оновлює тут статус кроків. Деталі кожного кроку — в `docs/steps/`.

## Ідея

Безкоштовна вебапка (для себе + потенційно друзів): список фільмів і серіалів
«хочу подивитись / дивлюсь / подивився». До кожного айтема: власна оцінка, нотатки,
кастомні посилання (де дивитись, цікаві матеріали тощо).

Ключові вимоги:

- **Local-first**: працює без реєстрації, дані в IndexedDB. Реєстрація (email+пароль)
  потрібна лише для синхронізації з хмарою (MongoDB Atlas, безкоштовний тир M0).
- **Пошук фільмів** через безкоштовні зовнішні API (TMDB — основне), мовами
  en/uk/ru, толерантний до одруків (наскільки дозволяє API).
- **Збагачення**: на сторінці фільму підтягуються дані з кількох API
  (рейтинги IMDb/RT з OMDb, «де подивитись» з TMDB watch providers).
  Дублікати між API відсіюються — юзер бачить одну сторінку з усім разом.
- **Синк із merge-інструментом**: при розбіжностях локальних і хмарних даних —
  зрозумілий не-девелоперу діалог «ось локальне, ось хмарне, що зберегти».
- UI: українська + англійська (перемикач), кастомна дизайн-система на CSS-змінних;
  тема м'яка і темна (див. ARCHITECTURE §8); адаптивність — і десктоп, і телефон
  (360px) для кожного екрана.

## Стек (рішення зафіксовані, див. docs/DECISIONS.md)

| Шар | Технологія |
|---|---|
| Фронтенд | Angular (остання стабільна, standalone components, signals) |
| UI-компоненти | Angular Material **тільки як функціональна база** (діалоги, автокомпліт, меню), повністю перетемізований під власну дизайн-систему на CSS custom properties |
| Локальне сховище | IndexedDB через Dexie.js |
| i18n | Легкий власний сервіс на signals + JSON-словники (uk/en), runtime-перемикач |
| Бекенд | Vercel Serverless Functions (`/api`, TypeScript, Node runtime) |
| БД (хмара) | MongoDB Atlas M0 (безкоштовний) |
| Аутентифікація | email + пароль, bcrypt, JWT |
| Зовнішні API | TMDB (основне), OMDb (рейтинги), опційно TVMaze / kinopoisk.dev |
| Хостинг | Vercel (фронт + api в одному репо) |

## Ролі та процес роботи

- **Архітектор/рев'юер (Fable/Opus, ця сесія)**: план, архітектура, ревью виконаного,
  правки в документах. НЕ пише основний код руками, крім дрібних фіксів після ревью.
- **Виконавці (Sonnet або інші дешевші сесії)**: беруть ОДИН файл із `docs/steps/`
  і виконують його від початку до кінця.

### Правила для агента-виконавця (ОБОВ'ЯЗКОВО)

1. Прочитай `CLAUDE.md`, `docs/PLAN.md`, `docs/ARCHITECTURE.md` і свій step-файл ПЕРЕД роботою.
2. Роби ТІЛЬКИ те, що в твоєму step-файлі. Не залазь у наступні кроки.
3. Після завершення: онови чекбокси нижче, допиши в свій step-файл секцію
   `## Результат виконання` (що зроблено, що відхилилось від плану, відомі проблеми).
4. Якщо щось неможливо зробити як описано — зроби мінімальне розумне рішення
   і ЗАДОКУМЕНТУЙ відхилення в step-файлі, а не мовчки міняй архітектуру.
5. Перевір, що `npm run build` і `npm test` (якщо є тести) проходять, перш ніж завершити.

## Що потрібно від власника проекту (Артема)

Реєстрації/ключі (всі безкоштовні), потрібні НЕ одразу, а перед відповідним кроком:

- [ ] **TMDB API key** — https://www.themoviedb.org/settings/api (потрібен до Step 05)
- [ ] **OMDb API key** — https://www.omdbapi.com/apikey.aspx, free 1000 req/день (до Step 06)
- [ ] **MongoDB Atlas** — кластер M0 + connection string (до Step 07)
- [ ] **Vercel-акаунт** + прив'язаний git-репозиторій (до першого деплою; локально можна без нього)
- [ ] Згенерувати `JWT_SECRET` (будь-який довгий випадковий рядок) (до Step 07)

Локально ключі кладуться в `.env.local` (в `.gitignore`!), на Vercel — в Environment Variables.
